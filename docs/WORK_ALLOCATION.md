# MineTurn 剩余任务与分工

更新：2026-10-08。负责人：**Codex（本对话）**、**DeepSeek v4.1**。

这是截至当前工作区的剩余工作总表，不把已完成事项重新列为开发任务。历史实现细节保留在 TASKS.md 和各专题文档。当前基线：Minecraft 1.21.1 / NeoForge 21.1.251 / Java 21，协议 21，298 项服务器 GameTest 通过（build/water-potion-boundaries.log）。

本文件是分工安排，**不表示任务已发送或已经开始**。当前会话不能直接调用 DeepSeek v4.1；由用户把文末任务说明交给该模型。没有另起模型冒充 DeepSeek。

## 优先级与分工原则

- P0：现有功能正确性、重复结算/物品复制/锁残留、发布前必须确认的行为。
- P1：通用能力与现有物品、表现收尾；优先于继续扩充原版怪物。
- P2：较大的扩展与原版 Boss 分阶段实现；不要求一次完成。
- 暂缓：已记录的可选范围，暂不影响核心版本交付；重新排期后再做。
- Codex 负责设计不明确、跨系统、高风险和共用框架；DeepSeek 负责输入输出明确、改动范围有限、可独立检查的任务。这是按任务边界分配，不是按模型能力作保证。
- 表中所有任务初始状态均为“待做”，依赖未满足的任务先等待。测试发现缺陷不代表相应功能从未实现。

## 明确取消或不开放（不再分派开发）

- 铁魔法等专有魔法模组适配；保留已有通用行动/API。
- 普通攻击击退、战斗换装及狼铠穿脱；独立技能位移与狼铠修复保留。
- 战斗内重锤额外机制、鸡蛋投掷、挖掘疲劳附加机制。
- 巨人 AI、资源型被动生物参战，以及给全部原版怪物强行增加差异机制。
- 战斗放置/破坏/工作方块互动；不为 TNT、床、重生锚、水晶、液体桶、打火石等开放原版操作。
- 不重复改已确认正确的弩 live/snapshot、payload 主线程处理、守卫者光束伤害、成功行动重置 30 秒倒计时。

## 推荐执行顺序

1. **立即并行准备**：Codex 做 A01–A04；DeepSeek 先做 D01–D03。D03 是测试表编写，不需要先打开客户端。
2. **现有功能收尾**：Codex 做 A05/A06/A10；DeepSeek 做 D04–D07、D09–D11。每项测试补缺先核对已有覆盖。
3. **通用表现与骑乘**：Codex 做 A07–A12；接口固定后 DeepSeek 接 D08。两条核心线由 Codex 顺序推进，避免同时修改状态与网络造成混淆。
4. **生物与 Boss**：Codex 做 A13–A18；DeepSeek 接已稳定部分的 D12。先保证共用能力，再逐 Boss 最小循环。
5. **附属模组**：Codex 做 A19/A20，DeepSeek 补配置/文档。暂缓表不自动插入当前队列。
6. **每批整合**：A21；只有成功整合与验证后才改总表状态。
