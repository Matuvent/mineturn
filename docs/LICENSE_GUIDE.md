**已知并接受的取舍**：LGPL 的传染性只作用于本模组本体。把 MineTurn 打包进整合包属于

这不是疏漏，而是刻意的决定：**"禁止商用"与"开源"在许可证体系里不兼容**。若采用 CC BY-NC
一类禁止商用的条款，本模组将不再是开源软件，CurseForge / Modrinth / FTB 等平台与正规整合包作者

至于"拿整合包盈利"本身：**售卖整合包本体已违反 Minecraft EULA**，由 Mojang 的条款约束，
本项目不再额外设限。

## 0. 先澄清一个常见误解（省你很多纠结）

仓库根目录的 `TEMPLATE_LICENSE.txt` 是 **NeoForge MDK 模板自带的 MIT 许可**：

```text
MIT License
Copyright (c) 2023 NeoForged project

This license applies to the template files as supplied by github.com/NeoForged/MDK
```

注意这一句限定：**"仅适用于由 MDK 提供的模板文件"**。

也就是说：

- 它**不是**你模组的许可证，也**不要求**你的模组用 MIT
- 它**不与你**的 `All Rights Reserved` **冲突**（很多人以为冲突，其实两者管的东西不同）
- 你**不需要**删它，也不需要改它——保留它是对 NeoForged 模板的署名，属于正确做法

`gradle.properties` 里的 `mod_license` 是**你模组自己**的许可证，这才是要决定的东西。

## 1. 许可证的两条主轴

选许可证本质上只回答两个问题：

### 主轴 A：别人能不能把你的代码做成闭源的衍生作品？

| | 宽松型（Permissive） | 传染型（Copyleft） |
| --- | --- | --- |
| 代表 | MIT、Apache-2.0 | GPL-3.0、LGPL-2.1、MPL-2.0 |
| 别人拿去改 | ✅ 可以，改完可以闭源 | ❌ 改了必须同样开源 |
| 别人拿去用 | ✅ 可以 | ✅ 可以（但衍生作品要开源） |
| 你想收改进 | ❌ 改进可能不回流 | ✅ 改进必须回流 |

### 主轴 B：别人能不能拿你的东西赚钱？

所有主流开源许可证（MIT / Apache / GPL / LGPL / MPL）**都允许商业使用**。「禁止商用」需要
另外的许可证（如 CC BY-NC），但那**不是开源许可证**，会造成一堆兼容问题。

## 2. Minecraft 模组行业的现实约束

这一节比法条更重要，因为它决定"社区会不会用你的东西"。

**约束 1：1.21.1 模组生态以 LGPL-2.1 为主流。**
NeoForge 自身是 LGPL-2.1，大量中大型模组（尤其库类与框架类）也是。原因很实际：
LGPL 允许**动态链接**（其他模组调用你的 API）而不要求对方开源，同时要求**改你本体**的人开源。

**约束 2：GPL-3.0 在模组圈很罕见，会制造兼容摩擦。**
如果有人想同时用你的模组和一个 GPL 模组，两者结合时会有许可证冲突的争议。
实际中大家常常无视，但正规发行方（整合包平台、商业服务器）会避开。

**约束 3：模组本身的法律地位本身有灰色地带。**
Minecraft 是 Mojang 的专有软件，模组通常被认为是对其的衍生/附加作品，受
[Minecraft EULA](https://www.minecraft.net/en-us/eula) 与
[Minecraft Usage Guidelines](https://www.minecraft.net/en-us/usage-guidelines) 约束。
你能授权的是**你自己的原创代码**（`133` 个 Java 文件 + 数据包 + 文档），
不能授权 Minecraft 本身。同时注意 Usage Guidelines 对**售卖模组本体**的限制
（一般允许捐赠/赞助，不允许把模组本身当商品卖）。

## 3. 五种常见选择的对比（按本项目相关性排序）

打分维度：**社区兼容性** = 别人会不会乐意集成/依赖你；**保护力** = 别人拿走改进后是否必须回流。

| 许可证 | 宽松/传染 | 允许闭源衍生 | 社区兼容性 | 保护力 | 本项目适配度 |
| --- | --- | --- | --- | --- | --- |
| **LGPL-2.1-only** | 弱传染（库级） | ✅ 可以（调用 API 不受限） | ⭐⭐⭐⭐⭐ 生态主流 | ⭐⭐⭐ 改本体须开源 | **最高** |
| **MIT** | 宽松 | ✅ 可以 | ⭐⭐⭐⭐⭐ 谁都认 | ⭐ 几乎无 | **很高** |
| **MPL-2.0** | 文件级传染 | ✅ 可以 | ⭐⭐⭐ 模组圈少见 | ⭐⭐⭐⭐ 改单文件须开源 | 中 |
| **Apache-2.0** | 宽松 | ✅ 可以 | ⭐⭐⭐ 有 NOTICE 负担 | ⭐ 几乎无（但含专利授权） | 中 |
| **GPL-3.0** | 强传染 | ❌ 不可以 | ⭐⭐ 会造成兼容争议 | ⭐⭐⭐⭐⭐ 最强 | 低 |
| All Rights Reserved | 专有 | ❌ 不可以 | ⭐ 别人不能合法用 | ⭐⭐⭐⭐⭐ | **最低（=不能算开源）** |

### 逐个说明

**LGPL-2.1-only**
- 别人**调用**你的 API（`CombatEffects.register`、`BattleManager.locked` 等）来写扩展模组 → **不受限**，可以闭源
- 别人**修改你的代码**后分发 → 必须提供修改后的源码
- 这是 NeoForge 自身采用的许可证，模组圈最熟悉，法务争议最小
- 缺点：文本较长；对"静态链接"的定义在模组场景下有点含糊（社区惯例上不纠结）

**MIT**
- 一句话：随便用，保留版权声明就行
- 优点：兼容性天花板，没有任何解释成本，任何人（包括商业服务器、整合包）都不会犹豫
- 缺点：如果有人 fork 你的模组加了 200 个动作然后闭源卖，你无权要求他开源
- 对本项目：你的核心价值在**战斗系统设计与数据包规范**，MIT 意味着它可能被广泛吸收

**MPL-2.0**
- 折中：**逐文件**传染。别人改了你哪个文件，那个文件要开源；新增文件可以闭源
- 比 LGPL 更清晰（没有"链接"的模糊性），但模组圈不常见，别人需要多读一遍

**Apache-2.0**
- 和 MIT 接近，额外提供**明确的专利授权**（对模组一般用不上）
- 额外要求：分发时要保留 `NOTICE` 文件、标注修改。对模组来说是不必要的负担

**GPL-3.0**
- 最强保护：任何人分发衍生作品都必须整体开源（含其整合的其它代码）
- 但正因如此，别人**不能**把 GPL 模组和闭源模组打包在一起而不产生争议 → 社区会回避
- 除非你就是要"强制一切开放"，否则不建议

## 4. 推荐

### 首选：**LGPL-2.1-only**

理由针对本项目：

1. **你本质上做的是一个框架。** `api/CombatEffects.java`（51 个已注册效果）、`BattleAccess` 受管接口、
   数据包规范——设计意图明显是"让别人扩展"。LGPL 的库级传染恰好匹配这个意图：
   别人写扩展模组可以闭源，改你的框架本体必须开源。
2. **与 NeoForge 生态一致。** 未来若有人想把 MineTurn 作为依赖，LGPL 是默认预期，不会产生摩擦。
3. **保护力适中。** 如果有人修好了你代码里的 bug 想私藏，LGPL 要求他回流。

**如果你更在意"最大传播、最少解释成本"→ 选 MIT。**
这也是完全合理的选择。区别只在：你放弃了对闭源 fork 的约束力。

**不建议 All Rights Reserved**：它意味着"别人不能合法使用、修改、分发"，
那就不该叫开源仓库——README 里必须写明，否则会一直被问"我能用吗"。

### 具体到你要填的值

```properties
# gradle.properties:33
mod_license=LGPL-2.1-only
```

（SPDX 标识符写法。若选 MIT 就写 `MIT`。）

## 6. 两个容易忽略的补充

**6.1 数据包的授权**
你的模组内容很大一部分是数据包 JSON（58 个动作 / 33 套 AI 配置 / 27 个 `.mcfunction`）。
许可证会一并覆盖这些原创内容，无需单独处理。
但如果你日后**发布独立的示例数据包**给别人单独下载，建议在数据包内也放一份说明。

**6.2 第三方代码与素材**
- 项目基于 NeoForge MDK 脚手架 → 已由 `TEMPLATE_LICENSE.txt` 覆盖，保留即可
- `assets/mineturn/` 下若有从别处引用的贴图/音效，**不能**用你的许可证覆盖，
  需要在 README 或 `LICENSE` 附注来源与原作者许可
- 若 `api/` 下参考了其它模组的接口设计（非代码复制），一般无需署名；但**逐行复制**则必须遵守对方许可证

**6.3 捐助与售卖**
常见做法是"模组免费 + 接受捐赠"。若想通过爱发电/Patreon 等接受支持，这与任何主流开源许可证都不冲突。
但**不要售卖模组本体**，那会触碰 Minecraft Usage Guidelines。
