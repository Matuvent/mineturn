# 远程判定

弓、弩已内置 `mineturn:shoot` 动作。将武器放到快捷栏，背包或副手准备普通箭，在战斗 GUI 中点击武器、选择敌人；准备约一秒后，指针从左向右移动，进入绿色区域时按一次**空格**。

成功即结算动作效果，失败不造成伤害。提前按键、错过区域或不提交直到超时都算失败。没有新的整回合操作倒计时；只有开始射击后，这次判定才有时限。

## 资源与目标

开始判定时就消耗一次主要行动、一份弹药和一点武器耐久，动作冷却立即按 AV 计算。命中、失败、超时和目标离场都不会退还这些资源。判定结束后仍可使用剩余移动距离；判定期间不能移动、结束行动或重复施放。

远程动作不使用物品组件的 `melee_range` 或动作的 `range` 限制选择距离，但目标必须是同场存活敌人并满足视线要求，命中结算时再次检查。距离影响绿色区域宽度。普通近战动作保持原有范围限制且没有此判定。

弓与弩使用即时命中结算，不生成持续实时飞行的箭，也不读取弩预装弹药。力量、火矢、无限、多重射击、穿透、快速装填及特殊弹药已接入，详见 [武器与特殊物品](WEAPONS_AND_ITEMS.md)。

## 数据包配置

动作位于 `data/<命名空间>/mineturn/actions/<名字>.json`，例如：

```json
{
  "name": "射击",
  "effect": "mineturn:projectile",
  "amount": 6,
  "range": 16,
  "cooldown_av": 100,
  "ranged": {
    "duration_ms": 1200,
    "near_width": 0.4,
    "min_width": 0.06,
    "distance_factor": 0.14,
    "ammunition": "minecraft:arrow",
    "ammo_count": 1
  }
}
```

`range` 目前仍是通用动作格式必填字段，但远程模式不将它用于距离上限。远程动作只能选择敌人，`self` 必须为 false，箭类动作 `consume=0`，弹药消耗单独配置；投掷物允许 `consume=1` 且 `ammo_count=0`。

| 字段 | 含义与限制 |
| --- | --- |
| duration_ms | 指针从左到右的时间，800–10000 毫秒，默认 1200 |
| near_width | 近距离命中区域占总条宽度的比例，0.02–1，默认 0.4 |
| min_width | 最小宽度，0.02–near_width，默认 0.06 |
| distance_factor | 距离衰减系数，0–10，默认 0.14 |
| ammunition | 弹药物品 ID，默认 minecraft:arrow，必须存在且不能是 air |
| ammo_count | 每次弹药数量，0–64，默认 1；0 可用于无需物品弹药的怪物动作 |

实际宽度为 `max(min_width, near_width / (1 + 距离 × distance_factor))`。区域以进度条中点为中心，距离按两个实体位置的三维距离计算，在开始判定时固定。标准物品映射和 `mineturn:combat` 数据组件都可以引用远程动作 ID，无需给物品增加另一种组件。

## 服务端与联机

服务端生成随机一次性 token，并**自行决定判定窗口在进度条上的位置**（随机分布于条中部 25%–75%，且按下前的引导时长也随机）。客户端只发送 token，不上报指针位置或命中结果；窗口边界随 Aim 包下发，客户端据此渲染绿色区域，但**无法提前算出应当按下时刻**——它只能等窗口出现后凭反应作答。

服务端按 token 校验射击身份、再按真实经过时间判断提交是否落在窗口内。重复、伪造、其他玩家、旧战斗的 token 不会再次结算。

使用本次开始时服务器测得的往返延迟做补偿，上限 250 毫秒；超时清理额外保留最多 250 毫秒的传输余量。高延迟、抖动或客户端卡顿仍可能造成画面与服务端结果的偏差，需要多人实测调参。该协议不声称能识别自动按键等客户端自动化。

计时使用现实单调时钟，暂停菜单不能停止服务端判定。普通 AV 冷却仍只随行动时间轴推进。其他参与者会收到开始射击、命中/失败和生命值更新，只有射手收到判定进度条。战斗结束、重载、射手或目标离场时取消尚未完成的判定。

网络协议升级为 20，客户端和服务端应同时更新 MineTurn JAR。

## 怪物远程动作

mcfunction 仍使用 `mineturn ai use <动作ID>`。怪物不操作玩家进度条，由服务器按同一距离公式计算概率并抽取命中；主手或副手可提供所配置弹药，也可配置 `ammo_count: 0`。未命中仍消耗主要行动和冷却。`on_action_resolved` 中 `mineturn ai query event_success` 返回实际命中是否成功。

自定义效果只会在命中后运行，所以远程动作也可以引用已有特殊效果接口。延迟效果的 `on_action_resolved` 仍表示施放完成，不代表未来延迟效果已经击中。

## 验证

服务器 GameTest 覆盖距离曲线、协议编解码、超出近战范围的命中、资源预付、重复/错误 token、提前提交、过期提交、无提交超时、目标离场及缺少弹药，以及**窗口位置服务端随机化**（窗口中心随机分布于 25%–75%、不同射击之间移动、命中必须落在窗口内）。GUI 已编译通过，进度条布局、键盘手感和真实联机延迟尚需游戏内复核。
