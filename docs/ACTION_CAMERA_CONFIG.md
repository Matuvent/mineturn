# 动作技能镜头配置

本文说明如何配置**动作演出镜头**（崩铁式技能机位）。这是**纯客户端表现**，不影响任何战斗结算。

> **状态**：近战 / 进食 / 饮用 / 射击四种基础预设**已实现并可直接配置**。
> 行动者**姿态动画**（举食物、挥剑等）属于 A11 范围，**尚未实现**——本文不含那部分。

---

## 1. 配置文件在哪

```
assets/<命名空间>/mineturn/animation_camera.json
```

模组自带一份，在 `assets/mineturn/mineturn/animation_camera.json`。
要改就自己做一个**资源包**，放同路径文件覆盖它（资源包优先级高于模组自带）。

**可独立安装的示例**：`examples/animation-camera/`（数值刻意与默认值不同，便于一眼确认生效）。

### 生效方式

| 方式 | 是否生效 |
| --- | --- |
| 启动客户端 | ✅ |
| 游戏内切换资源包 / F3+T 重载资源 | ✅ |
| 服务器 `/reload` | ❌ **不影响客户端资源** |

> **注意**：这是**客户端资源**。服务端装了什么不重要，每个客户端各自加载自己的镜头配置；
> 服务器 `/reload` 只重载数据包，不会重载客户端资源。

### 写坏了会怎样

解析失败时**保留上一套已生效的规则**（不会清空、不会崩溃），并记录一条错误日志：

```
Invalid animation camera file <file>: <原因>
Keeping the previous N animation camera rules because a file was rejected
```

自建资源包时留意日志，或直接用 `tools/validate_examples.py` 静态检查。

> 早期实现曾在解析失败时仍写下"半张表"，导致**整张规则表被清空**（日志还会显示 `rules: 0`，
> 看起来像正常加载）。现已改为拒绝即保留旧表。

## 2. 字段含义

```jsonc
{
  "camera": { ... },        // 默认规则：未被 actions 覆盖的动作都用它
  "actions": {              // 按动画 id 覆盖
    "melee": { ... }
  }
}
```

单条规则（所有字段都可省略，省略即取内置默认）：

| 字段 | 单位 | 含义 |
| --- | --- | --- |
| `side` | 格 | 镜头相对行动者**右方**的偏移（始终非负） |
| `front` | 格 | 镜头沿行动者**朝向**的偏移。**负值 = 在身后**（过肩），正值 = 在身前 |
| `lift` | 格 | 镜头抬升高度 |
| `width_base` | 格 | 瞄准点前移基数（**不影响机位**） |
| `width_scale` | 倍 | 瞄准点前移系数，按实体宽度缩放（**不影响机位**） |
| `min_distance` | 格 | 到瞄准点的**最小**距离（沿视线方向），防止镜头插进模型体内 |
| `aim_distance` | 格 | 瞄准点在角色**前方**的基础距离；固定它可让构图不随目标远近变化 |
| `aim` | 枚举 | 镜头看向什么：`actor`（行动者）\| `target`（目标）\| `midpoint`（两者之间，默认） |
| `blend_out_ms` | 毫秒 | 演出结束**回落到自由镜头**的过渡时长；`0` = 立即回弹。范围 `0..2000`，默认 `80` |

### 构图：过肩

默认是**过肩机位**：镜头在行动者**右后方**，看向**行动者与目标之间**，
因此攻击者（前景）与被攻击者（中景）**同时入画**。

这靠三个字段配合：

| 字段 | 过肩取值 | 作用 |
| --- | --- | --- |
| `front` | **负值**（如 `-1.7`） | 把镜头放到攻击者身后 |
| `side` | 正值（如 `0.95`） | 偏到右肩外侧，避免角色挡住目标 |
| `aim` | `midpoint` | 看向两者之间，而不是只盯着目标 |

`front` 之所以允许负值，就是为过肩构图。自我指向的动作（进食/饮用）用**正值**
（镜头在身前）配 `aim: actor`（看向自己）。

### 切镜是瞬间的

**进入技能机位是硬切，没有任何过渡动画。** 早期版本用 250ms 把镜头"推"过去，
实际体验是镜头绕着人物晃过去，很晕，因此改为瞬间切换。

`blend_out_ms` 只控制**结束时的回落**，不控制切入。默认 80 毫秒只是为了避免生硬跳回；
想要完全瞬时，把它设为 `0`。

**机位**（不随体型变化）：

```
右方 = side
前方 = front        （负值 = 角色身后）
高度 = lift + 角色身高 × 0.05
```

**瞄准点**（随体型微调，避免大体型挡住自己）：

```
瞄准点 = 角色眼睛 + 前方 × (aim_distance + width_base + 实体碰撞箱宽度 × width_scale)
```

### ⚠️ 机位为什么不随体型缩放

早期版本把碰撞箱项**同时加到 `side` 和 `front`** 上，结果对宽体生物是灾难性的：

| 生物 | 宽度 | 宽度项 | 实际 `side` | 实际 `front` | 后果 |
| --- | --- | --- | --- | --- | --- |
| 僵尸 | 0.60 | 0.30 | 1.25 | -1.40 | 正常 |
| **劫掠兽** | **1.95** | **0.99** | **1.94** | **-0.71** | **镜头跑到侧边，攻击者出画** |

`front` 的身后偏移**几乎被宽度项抵消**，镜头从"右后方"变成"右侧"。

现在：**机位只用 `side` / `front`**，碰撞箱只推远**瞄准点**。
`width_scale` 对 1.95 宽的劫掠兽约贡献 1 格前移，保证它不糊满屏幕。

> 你只需要按**普通体型**的观感调 `side` / `front`；大体型会自动前移瞄准点。

取值必须是有限数：`side`、`lift`、`width_base`、`width_scale`、`min_distance`、`aim_distance` 为 `0..64`，
`front` 为 `-64..64`（可负），`blend_out_ms` 为 `0..2000`，`aim` 必须是三个枚举之一。
任一字段越界或非法，**该文件被整体拒绝并保留上一套规则**。

## 3. 动画 id 与动作的对应

服务端按动作的 `effect` 决定用哪个动画 id，客户端据此取配置：

| 动画 id | 对应 effect | 优先级 | 典型动作 |
| --- | --- | --- | --- |
| `mineturn:melee` | `damage`、`weapon_melee`、`mob_melee`、`species_melee`、`slime_melee`、`vindicator_strike`、`heavy_strike` | **200（打断）** | 近战、怪物近战 |
| `mineturn:ranged` | `projectile`、`firework`、`skeleton_arrow`、`mob_crossbow`、`pillager_charge`、`player_trident`、`drowned_trident`、`player_snowball`、`snowball_support`、`splash`、`lingering`、`wind_burst`、`ghast_fireball` | **200（打断）** | 弓弩、投掷、药水、风弹 |
| `mineturn:eat` | `food`、`eat`、`native_food` | 50（排队） | 进食 |
| `mineturn:drink` | `drink` | 50（排队） | 喝药水、喝牛奶 |
| `mineturn:generic` | 其它一切 effect | 100 | 兜底 |

**任何动作都至少落到 `generic`**，所以不会出现"某个动作没有镜头"。

### 优先级的作用

演出只有一个镜头，多个动作同时发生时按优先级仲裁：

- **更高**优先级 → **立即打断**当前演出
- **相同**优先级 → **替换**（最新动作更值得展示）
- **更低**优先级 → 进**待播槽**等待，播完自动接上（不会"弹回自由镜头再切回去"）

所以攻击（200）会打断进食（50），而进食会等攻击播完。

### 想区分冲刺/激光等其它动作？

目前**不能**在数据包里给任意动作指定自定义动画 id——服务端用的是内置映射表。
这是刻意的：**让数据包直接指定动画 id 属于 A11 的 schema 工作**（尚未实现）。
当前可用的扩展方式是**按 effect 覆盖**：属于同一 effect 的动作共享同一 id 与同一套镜头。

## 4. 四种基础预设（默认值）

| 动画 | side | front | lift | width_base | width_scale | min_distance | aim | 取景 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `melee` | 0.95 | **-1.70** | 0.85 | 0.5 | 0.5 | 1.7 | `midpoint` | **过肩**：右后方约 1.4 格，越过肩膀看向两者之间 |
| `ranged` | 0.85 | **-1.90** | 0.95 | 0.5 | 0.5 | 1.8 | `target` | **过肩**：再远一点，指向目标方向 |
| `eat` | 0.75 | 0.90 | 0.45 | 0.4 | 0.4 | 1.6 | `actor` | 身前偏右，看向食用者自己 |
| `drink` | 0.80 | 0.90 | 0.50 | 0.4 | 0.4 | 1.6 | `actor` | 与进食相近，略高 |
| `generic` | 0.90 | **-1.60** | 0.80 | 0.5 | 0.5 | 1.6 | `midpoint` | 与近战相同的过肩兜底 |

> 表里的 `side` / `front` 是**配置值**，实际还会加上碰撞箱项：
> 对 0.6 宽的普通生物，近战实际约为**右 1.25 格、后 1.40 格**。

进食/饮用**看向行动者自己**（看不到对方），近战/远程/兜底**过肩并看向目标一侧**。

## 5. 调参建议

| 想达到的效果 | 调什么 |
| --- | --- |
| 镜头整体离角色更远 | 增大 `side`，并把 `front` 调得更负 |
| 只让镜头更靠右（少挡目标） | 增大 `side` |
| 想让镜头更靠后（角色更大） | `front` 更负 |
| 想让镜头到**身前**（不要过肩） | `front` 改为正值，并把 `aim` 改成 `target` |
| 目标被角色挡住 | 增大 `side`，或把 `aim` 从 `midpoint` 改成 `target` |
| 只看到角色看不到目标 | `aim` 改成 `target` |
| 大怪物太近、糊一脸 | 增大 `width_scale`（让宽体被推得更远） |
| 高个子生物被切头 | 增大 `lift` |
| 镜头插进模型里 | 增大 `min_distance` |
| 结束回落太生硬 / 还嫌晃 | 调 `blend_out_ms`；想要瞬时回弹设为 `0` |
| 贴墙时镜头卡墙 | 无需配置：机位落入方块时会自动沿视线夹到遮挡前 |
| 进食/饮用镜头太近、看不清 | 增大 `side` 或 `min_distance` |

**调参流程**：改 JSON → 进游戏（或 F3+T）→ 触发对应动作 → 看效果。
每次只改一个字段，否则分不清是哪个起的作用。

## 6. 与其它系统的关系

| 系统 | 关系 |
| --- | --- |
| 战斗结算（伤害、消耗、冷却） | **完全无关**。镜头是纯表现，不影响任何数值 |
| 移动距离 / AV 时钟 | **无关**。演出用现实时间计时，不推进 AV |
| 战斗外的自由镜头 | 演出结束后**平滑回落**到玩家原来的自由镜头 |
| 行动者姿态动画 | **未实现**（A11）。目前只有镜头，角色身体不会做动作 |
