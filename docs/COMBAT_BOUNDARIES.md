# 战斗边界

## 场外攻击

未授权的实时攻击涉及参战者时，原有伤害拦截继续生效。场外攻击者只有在当前战场范围内、仍存活、未参加其他战斗且符合参战配置时才能加入；不补发此次被拦截的伤害，也不抢占当前回合。

加入时记录攻击者与被攻击者的直接敌对关系，并将被攻击者记为攻击者的优先目标。普通中立生物不再仅仅入列却失去敌人，也不会因此自动敌视旁观玩家。僵尸猪灵、蜜蜂等专用愤怒规则仍有各自限制。本组不实现战斗合并。

## 爆炸推动

原版爆炸的伤害与速度增量是分开结算的，取消伤害事件不足以阻止推动。新增 ExplosionKnockbackEvent 处理：当受影响实体被战斗锁定（含受控坐骑），或爆炸归属的生物已被战斗锁定时，将该次爆炸速度增量置零。原版爆炸伤害仍走既有伤害边界。

正常场外实体之间的爆炸伤害与推动不受影响；战斗技能显式调用强制位移接口的行为不变。本组不提供区域方块防爆，不会阻止 TNT 或其他场外爆炸破坏战场地形。

## 验证与后续

自动化验证真实箭矢归属伤害触发中立增援、零首击伤害、原目标优先、旁观者隔离、重复攻击不重建成员，以及真实原版爆炸的参战者保护、场外正常伤害/推动和参战来源隔离。

跨战场直接实时伤害与状态隔离见下方第二组；环境变化与区域合并仍需后续分组完善。多人客户端移动、音效和画面需要实际联机验收。

## 第二组：场外药水与状态

- 原版喷溅药水和原版药水云跳过被战斗锁定的目标（含坐骑），同时拒绝已参战拥有者的遗留药水对场外实体继续生效。持续状态与瞬间治疗/伤害均受约束，不限于伤害取消。
- 每个目标和每次瞬时效果结算前重新检查，避免同一轮爆发途中建立战斗后仍继续施加后续瞬时效果。
- 带实体来源的原版 addEffect/forceAddEffect 使用 MobEffectEvent.Applicable 拒绝未授权且涉及战斗锁的状态应用；正常原版场外交互保留。
- MineTurn 战斗喷溅走已授权执行器；BattleCloud 继续通过所属战斗参与者与视线过滤，并按 AV 更新，不套用原版实时药水云的禁止规则。
- 两个独立战场之间的原版直接攻击及带来源状态不会合并战斗、转移成员、推进回合，也不产生伤害或新状态。

无来源的状态设置（包括部分命令/模组直接调用）不在本组统一拦截范围内；无法由此推断所有信标、第三方被动效果和绕过原版事件的修改均已隔离。第三方直接修改生命值或已有状态对象，也不由药水拦截自动覆盖。水瓶的灭火、方块修改和其他环境变化仍需单独审计。

测试覆盖真实原版喷溅和药水云的治疗/中毒、普通场外目标保留、参战拥有者隔离、两场战斗的伤害/状态/成员归属，以及授权战斗效果不被误拦截。

## 第三组：外部推动与窒息

- 拦截战斗锁定实体的原版 PISTON、SHULKER、SHULKER_BOX 移动，包括受控坐骑。检查发生在位置更新之前，不再依赖下一次战斗 tick 拉回。
- 既有战斗路径、传送和技能位移继续由各自执行器提交；未参战实体及离场实体的推动保持原版行为。
- 地形改变可能把实体埋入方块。战中通过原版 isInWall（眼部碰撞与方块 suffocating 判定）检查窒息，使用原版 inWall 伤害来源。首次遇到窒息的逻辑 tick 结算 1 点，持续窒息每 10 个逻辑 tick（50 AV）再结算一次；离开后重置间隔。伤害仍走原版免疫/减伤事件。
- 窒息不随玩家思考时间推进。实体离战后恢复原版实时窒息处理。

本组不阻止活塞或外部爆炸修改方块，也不自动把被埋实体移出障碍。水流、信标、其他无来源状态及更多环境接触规则仍需后续审计。
