# MineTurn 基础原型

目标版本：Minecraft 1.21.1 / NeoForge 21.1.251 / Java 21。

## 试玩

安装客户端与服务端相同的模组。生存模式下，在平坦地面攻击一只普通僵尸；只要双方都存活，就进入战斗。创造、旁观和未配置的怪物不进入此原型。现已支持单人可控制生物坐骑的陆地骑乘战斗，细节和限制见 [MOUNTED_COMBAT.md](MOUNTED_COMBAT.md)。

进入战斗后自动打开透明战斗 GUI，并切换到独立第三人称观察镜头。底部 9 个按钮与快捷栏逐一对应，右下角提供疾跑、移动、撤退、逃跑和结束行动。不可用动作会置灰，悬停查看原因。支持多名玩家协同对抗多只怪物。左上角“序列”预测未来 16 次行动，“全员”列出所有参与者及下一次行动所需 AV；当前行动者单独显示。鼠标停在队列上滚轮可查看后续条目。

### 镜头与鼠标操作

- 普通移动鼠标只移动指针，不改变视角或角色朝向。
- 在场景中按住左键拖动旋转镜头；拖动不会同时触发攻击或移动。
- 滚轮缩放，Shift + 左键拖动平移焦点，F 聚焦玩家。
- 点击武器按钮（或数字 1—9）后，单击可见敌人确认攻击；食物等自身动作可直接执行。
- 点击移动后，将鼠标移到地面。黄色表示等待服务器检查，绿色表示可到达，红色表示无效；在绿色落点上单击执行移动。
- 右键取消当前选择。Esc 先取消选择，再按可打开暂停菜单；返回游戏后恢复战斗界面。
- T 打开聊天，斜杠打开命令。命令仍作为备用操作入口。
- 玩家操作没有倒计时，必须点击“结束行动”才交出剩余机会。敌人仍自动行动。

客户端同时停止输入与移动预测，服务端继续校验。退出战斗、死亡或断线后恢复原来的相机模式和鼠标控制。需要重启游戏加载新版代码，`/reload` 只能更新数据包。

| 命令 | 用途 |
| --- | --- |
| `/mineturn` | 显示行动者、战斗时间、敌人血量、距离、物品动作 |
| `/mineturn attack` | 使用当前快捷栏物品的 `mineturn:melee` 动作；空手也能使用 |
| `/mineturn use 0 mineturn:melee` | 使用背包槽位 0 的指定动作 |
| `/mineturn move -2 0` | 沿世界 X 方向移动 -2 格，Z 方向不变 |
| `/mineturn sprint` | 消耗主要行动，将当前剩余移动距离翻倍 |
| `/mineturn retreat` | 消耗主要行动，允许本回合脱离近身控制 |
| `/mineturn flee` | 与敌人碰撞体距离至少 10 格时逃跑，消耗主要行动 |
| `/mineturn end` | 结束本次行动，放弃未使用的机会 |
| `/mineturn abort` | 管理员紧急解除当前战斗，权限等级 2 |

背包槽位 0—8 是快捷栏，9—35 是背包其他槽位。聊天菜单会自动列出有配置的物品动作。

每次轮到角色时获得一份移动距离，以及默认各一次的主要行动和次要行动；次数可由属性及技能接口调整，详见 [回合资源](TURN_RESOURCES.md)。玩家基础移动预算 4 格，移动速度属性按比例影响预算，基础预算上限 12 格。移动按实际水平路径长度扣费，剩余距离足够即可分次移动，不消耗主要行动。疾跑消耗主要行动，将当前剩余距离翻倍，例如先走 1 格，再疾跑：剩余 3 格变为 6 格。下回合恢复正常预算。界面显示剩余距离，点击结束行动交出回合，玩家操作有约 30 秒期限，成功行动后重置；移动动画和远程判定期间暂停计时。

周身范围默认 1.5 格，受遮挡限制。一次路径可以进入并继续靠近敌人，但不能离开或穿过控制区；停在敌人周身范围后，再次移动需要先撤退。撤退消耗主要行动，解除本回合近身移动限制；疾跑不能代替撤退。

移动沿直线跟随实际方块碰撞表面：每次上台阶最多一格，可以连续走多级台阶，下台阶没有人为高度上限，必须有可达落点。检查头顶、整条路径、实体碰撞、世界边界及支撑。鼠标落点整条路径不合法时不移动、不扣距离；备用命令保留遇阻提前停止。上升和下降均按水平距离扣移动预算，下降另外结算摔伤。后续已补充玩家陆地点选绕障和水下战术移动，规则见 MOBILITY_AND_SKILLS.md；玩家 GUI 陆地和水下已支持逐步移动动画；状态机陆地追击已支持绕障，陆地/飞行/水下状态机追击均支持位移动画；函数 AI 也可通过 move_async 接入动画（见 ASYNC_AI.md）；三维追击及玩家水下点选也已支持有界绕障；主动跳跃和备用移动命令动画仍待实现。

### 自动下落与摔伤

玩家空中入战、空中加入增援或脚下支撑消失时，会立即落到下方支撑，不消耗行动/移动预算。入战前累计的 fallDistance 加入本次剩余落差，避免通过入战免除摔伤。普通战术下落按每次实际落地分别结算，致死时立即移除参与者并结束没有对手的战斗。

基础伤害遵循本项目 1.21.1 的原版流程：`ceil((下落距离 - 安全下落距离) × 落地方块倍率 × 实体摔伤倍率)`，结果不大于 0 时不扣血。默认安全下落距离为 3 格、倍率为 1，例如下落 6 格造成 3 点伤害（1.5 颗心）。通过原版方块 fallOn 与实体伤害方法处理落地方块、摔落保护、抗性和游戏规则；缓降/漂浮免除本次摔伤。不会模拟实时自由落体导致的最后一 tick 距离误差。自动落下遇到液体表面会停止并清除本次落差；液体持续伤害尚未接入战斗时间系统。

规则参考 [Minecraft Wiki：Damage](https://minecraft.wiki/w/Damage#Fall_damage)，具体计算以工程内 1.21.1 源码为准。

## 增援与多目标

战斗区域以初始双方中点为固定中心，水平半径 16 格、上下 6 格，最多 32 名参与者。每 10 tick 检查附近生存玩家和有数据包配置的敌对生物，不抢占其他战斗的实体。所有玩家暂属同一阵营，怪物为敌方；普通被动生物不会因为路过自动加入。

增援从完整的 10000 行动距离开始排队，不获得额外先手，不重置其他人的进度。点击武器按钮后可选择任意合法敌方目标，命令入口默认选择最近敌人。

击败一只怪物只移除该怪物；一方没有存活参与者时结束战斗。逃跑要求距离所有敌人至少 10 格，只让逃跑者离场；留在区域内不会立即重新加入，离开区域后再次进入或主动攻击则可以重新参战。断线玩家暂时直接离场，其他人的战斗继续。

## 行动时间

`mineturn:agility` 属性默认 100，行动距离 10000。调度器一次推进到下一次行动，不按现实时间等待。先手额外行动不推进时间。同刻行动按稳定入场顺序处理。改变敏捷保留已经积累的行动进度。

玩家使用自身敏捷属性；怪物有效敏捷 = 自身敏捷属性 × 数据包 agility / 100。管理员可以通过原版 `/attribute` 命令调整属性。

原版自然回血在战斗中暂停。每经过 100 行动值，若自然回血规则开启、饥饿值至少 18 且生命未满，则恢复 1 点生命并消耗 1 点饱和度，不足时消耗 1 点饥饿值。不是原版回血速率的精确复刻。

## 数据包布局

数据包根目录包含 `pack.mcmeta`，1.21.1 使用 `pack_format: 48`，以及：

```text
data/<命名空间>/mineturn/actions/<动作名>.json
data/<命名空间>/mineturn/mobs/<配置名>.json
data/<命名空间>/mineturn/items/<配置名>.json
```

模组自带示例位于 `src/main/resources/data/mineturn/mineturn/`。覆盖相同资源路径可替换默认定义。同路径按数据包优先级整文件覆盖；不同文件映射相同生物或物品时，顶层 priority 较高者获胜，最高优先级仍重复则拒绝加载。亦支持按实体列表、实体标签、命名空间批量匹配，以及可继承的 AI 模板，详见 [批量 AI 使用说明](BATCH_AI.md)。

`/reload` 会结束现有战斗并清理其 AV 定时函数，再检查字段范围、效果类型、状态目标、动作引用及函数入口。新 JSON 与原版函数库匹配后一起启用，校验失败保留旧规则。首次加载失败时没有可用规则。

### 动作

```json
{
  "name": "大口撕咬",
  "effect": "mineturn:damage",
  "amount": 6,
  "range": 1.5,
  "self": false,
  "consume": 0,
  "cooldown_av": 0
}
```

效果类型：`mineturn:damage` 基础伤害（经过护甲减伤）、`mineturn:heal` 治疗、`mineturn:food` 食物。食物必须以自身为目标且 `consume` 为 1，会读取物品原有食物属性。默认示例不包含特殊药水/附魔食物。

所有动作消耗一次主要行动。`consume` 表示消耗物品数量；伤害动作使用可损坏物品时额外损耗 1 点耐久。当前默认剑和空手都是数据包指定的 4 点基础伤害，没有完整接入武器攻击力、附魔和攻击速度；可以通过不同动作区分武器。

`cooldown_av` 绑定战斗内的角色和动作 ID，更换物品不能绕过同一个动作的冷却。冷却只存在于战斗会话内存中，**跨战斗与跨重启不持久化**；默认包因此不启用技能冷却。

### 函数 AI

现已支持原版 `.mcfunction` 的入战、回合、动作完成和离场回调，以及战斗专用命令、AV 定时函数和宏参数。其他模组 JAR 与世界数据包都可新增和覆盖定义，详见 [函数 AI 使用说明](FUNCTION_AI.md)。

### 怪物状态机

参考自带 `mobs/zombie.json`：通过 `entity` 指定实体 ID，`agility` 指定基础敏捷，`reach` 指定近身范围，`initial_state` 指定初态。每个状态有 `behavior`、有序 `transitions` 和可选 `choices`。

已提供行为：`approach`（追击）、`weighted_action`（加权动作）、`wait`（等待）。条件：`in_reach` 与 `out_of_reach`。每回合最多转换一次，追击移动完成后不会追加攻击。攻击状态在合法且冷却完毕的动作间抽取，无合法动作则等待。

默认僵尸：70 权重利爪（4 基础伤害），30 权重撕咬（6 基础伤害）。当前选择最近敌方玩家，每只怪物独立保存状态与冷却，不包含完整仇恨表。

### 物品映射与组件

```json
{
  "items": ["othermod:steel_spear"],
  "combat": {
    "enabled": true,
    "actions": ["mineturn:melee"],
    "melee_range": 3.5
  }
}
```

物品堆叠上的显式 `mineturn:combat` 组件优先于数据包映射，`enabled: false` 可禁止此件物品的战斗使用。组件字段与上述 `combat` 对象相同。例如：

```mcfunction
give @s minecraft:stick[mineturn:combat={enabled:true,actions:["mineturn:melee"],melee_range:3.5}]
```

组件覆盖玩家动作的近战距离。未配置物品默认禁用。远程动作与判定小游戏现已实现：弓、弩、三叉戟、雪球、风弹与地面药水投掷均使用窗口判定，配置与难度规则见 [远程判定说明](RANGED_COMBAT.md)。

## 扩展接口

`api/CombatEffects.java` 提供可注册的效果执行器：在公共初始化期间调用 `register(ResourceLocation, Effect)`，数据包随后可以用该 ID 作为 `effect`。`validate` 负责无副作用检查，`execute` 在服务端提交行动后调用一次。上下文包含施放者、目标、物品、动作配置与当前行动值时间。

`BattleManager.locked(entity)` 可用于适配层禁止非回合施法；`battleTime(entity)` 返回当前战斗时间，未参战时为 NaN。这只是扩展起点，不代表已兼容任何魔法模组。实际接入仍需要拦截其施法入口、接管资源和转换进出战斗的冷却。

## 原型边界

- 没有自定义阵营、战斗合并或完整地形寻路。玩家之间的敌对只能通过互相攻击建立，尚无 PvP 阵营配置。镜头为战场附近的轨道观察和平移，带墙体碰撞；不是无限制飞行模式。
- 原版移动、攻击、交互、挖掘、物品使用、背包操作及换手等主要玩家数据包在服务端被拦截。聊天和管理命令保留。客户端同时冻结移动输入与角色移动计算。
- 药水效果、周期伤害、燃烧、氧气与饥饿已换算到 AV 时钟（5 AV = 1 原版 tick），详见 [AV 状态时间轴](AV_STATUSES.md)。战斗外的环境伤害仍被拒绝；其余实体计时尚未全部统一。这些是逐步替换中的原型策略，不适合作为完整生存平衡。
- 未保护战场地形，其他玩家、流体、活塞等外部干预尚未全面隔离。
- 离线暂时解除战斗，没有离线身体、重连恢复与战斗持久化，不适用于防作弊多人正式服。
- 退出战斗后恢复原版逻辑；不永久修改生物 NoAI、玩家游戏模式或能力。

## 构建与验证

使用 Java 21：`gradlew.bat build`。执行 `gradlew.bat runGameTestServer` 验证实际 NeoForge 加载和服务器逻辑。测试服务器使用独立 `run-gametest` 目录，不使用试玩客户端的 `run` 目录。测试类仅在开发环境注册。

当前共 **289 项 `@GameTest`**（`BattleExtensionGameTests` 257 项 + `BattleGameTests` 32 项），`runGameTestServer` 报告 **287 项 required 全部通过**，另有 2 项位于非 required 命名空间。覆盖范围（节选）：

- **行动与时间**：行动顺序与变速、同刻排序、小数 AV、先手行动、等待不回血与行动值回血、玩家操作期限与超时推进
- **移动**：移动/撤退/疾跑预算、分次移动、台阶与头顶碰撞、高处摔伤、空中入战保留落差、支撑消失、缓降、逐步移动动画与动态障碍停步、陆地/水下绕障、骑乘共同移动
- **判定与拦截**：秒杀不入战、原版伤害与移动拦截、组件禁用优先级、重复行动拒绝、非法落点及过期请求拒绝、进入/靠近控制区、禁止穿行、逃跑后防立即重新加入
- **数据包**：加载与非法数据拒绝、映射优先级与冲突、AI 模板继承、真实数据包重载覆盖与失败回滚、来源溯源
- **函数 AI**：原版函数宏、嵌套调用、回调身份、行动预算、AV 时间点、递归上限、`on_move_finished` 权限与成功标志
- **物品与远程**：弓弩与多重射击（含逐箭耐久、中途损坏、最后一箭快照）、药箭/光灵箭、烟花、三叉戟（属性/投掷/忠诚/引雷/穿刺）、雪球、风弹、地面与友军药水投掷、副手盾牌、不死图腾、护甲与附魔原版行为、冷却入战继承与离战恢复
- **进阶系统**：区域效果、陷阱与机关、延迟动作、召唤生命周期、授予行动与资源、传送与位移、战斗边界隔离

**GameTest 不验证实际客户端画面与鼠标手感。** `runGameTestServer` 是专用服务端，`BattleClient`、`BattleScreen`、各渲染器与 `ProjectileAnimations` 均不在其执行范围内；镜头、插值平滑与联机表现只能实机验证。详见 [代码审查](CODE_REVIEW_2026_10_07.md)。
