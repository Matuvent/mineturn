# 物品功能盘点与制作计划

更新日期：2026-10-04。适用版本：Minecraft Java 1.21.1 / NeoForge。

本文件记录当前实现和后续物品工作，作为 [开发任务表](TASKS.md) 中“物品功能”的具体清单。依据当前代码、内置物品 JSON 和已有实现说明整理；计划项不代表已经实现。后续按组制作，每组完成后更新状态。

## 1. 范围与原则

- 优先完善通用战斗和常用物品，之后再做暮色森林、灾变附属模组。
- 尽量读取原版组件、属性和接口：武器攻击属性、附魔、食物营养与饱和度、药水内容、耐久、容器和烟花内容，不为每个物品复制一套固定数值。
- 原版物品完整兜底注册已经存在，但未适配物品会明确禁用；“登记了所有物品”不等于“所有物品都能在战斗中使用”。
- 保持数据包物品/行动 JSON、物品战斗组件的覆盖与新增能力。数据包可以组合现有执行器；全新 Java 行为仍需要模组提供执行器，不能承诺任意物品只写 JSON 就能完整兼容。
- 行动成本复用可配置的主要/次要行动次数。以下新增物品默认建议消耗一次主要行动；最终数值和特殊成本在对应组实现时确定。
- 冷却和持续效果使用 AV。付费、消耗、耐久、容器返还各处理一次；预览不扣费，已提交远程判定失败按既有规则承担成本。
- 普通攻击继续不产生击退。风弹、激流、风爆等明确的位移技能可使用独立位移接口，不能把普通攻击击退整体重新打开。
- 战斗中继续禁止放置/破坏方块、工作方块互动。涉及改变地形的物品不因加入物品计划而自动开放。

## 2. 当前已经可以使用的物品

“已实现”指已有战斗执行路径；不表示所有附魔、模组变种和客户端表现都已验收。

| 盾牌 | 盾牌 | 一次主要行动举盾；下一次自身行动前最多挡一次符合条件的攻击；方向、耐久及破盾 AV 冷却 | 副手入口和装备切换体验 |
| 风弹 | 风弹 | 远程判定、原版伤害类型、受约束的强制位移、碰撞与摔伤 | 自身风跳/地面投放若制作需独立入口，当前不算完成 |
| 修复材料 | 铁锭、犰狳鳞甲 | 铁锭修复友军铁傀儡；鳞甲修复自己狼的狼铠；材料与行动各消耗一次 | 其他装备的穿脱/修复不自动包含在内 |

## 3. 分组制作清单

### 第一组：现有物品一致性与选择体验（P0，先做）

这组优先消除已有功能中的缺口，再新增武器。

- [x] **弩的原版已装填弹药**：读取 `CHARGED_PROJECTILES`，支持普通箭、药箭、光灵箭、烟花的单发或三发相同组件装填；提交时清空装填，不扣背包弹药，未命中/取消不返还。射线数量读取实际装填快照。空弩保持现有即时射击路径，不新增蓄力规则；动作类型不匹配时无消耗拒绝。非原版混合组件/特殊数量装填明确拒绝并保留，不算已兼容。客户端装填图标与提示待实测。
- [x] **弹药选择**：物品射击动作增加具体弹药堆叠选择，覆盖背包 0–35 与副手；每页六组，悬停查看原版效果/烟花说明。服务端重检槽位、类型、全部组件与单组所需数量，提交后保存实际弹药快照；变化或不足时无消耗拒绝。原版已装填弩跳过选择并优先使用装填。命令及未显式选择的旧入口仍按背包顺序选取；条件授予行动暂不提供选择界面。客户端显示待实测。
- [x] **友军与地面药水投放**：喷溅/滞留药水增加友军目标及合法表面落点、服务端预检、范围参考圆环；保留敌我共同受影响、遮挡、战场边界和消耗规则。地面命中前重检，失效不退款；滞留云固定于已选位置。客户端布局和圈线待实测。
- [x] **消耗与容器第一批**：普通食物改用原版 Player.eat，保留 FOOD 恢复/效果、最后一份原槽位变容器、叠堆容器入包或满包掉落。特殊弹药、投掷药水、食物和通用消费尊重原版无限材料能力，仍支付行动/冷却；已装填弩发射后清空装填。没有开放创造模式参战，测试通过生存角色的 instabuild 能力隔离核验消费接口。
- [x] **玩家弩耐久核验**：箭逐发请求扣 1、烟花逐发请求扣 3，调用原版耐久接口；武器中途损坏停止后续射线，保留已发射部分与组件快照。覆盖预装弹药、未命中和耐久附魔对照；不增加背包弹药或行动次数消耗。
  - **已实现 vs 待做**：玩法机制**已实现且服务器测试通过**。
  - **待做（测试缺口，非机制缺陷）**：`crossbowUnbreakingMatchesNativePerProjectile` 是**直接调用**
    `CombatProjectiles.payCrossbowDurability(player, bow, bow.copy(), ...)` 并自造快照，绕过了
    `BattleSession.use()` 的真实接线；若将来改坏 `use()` 传入的参数，那条测试不会报警。
  - **该缺口已由另一条测试补齐**：多条射击用例（如 `BattleExtensionGameTests` 中带 `loaded` 参数的
    用例，实机走 `battle.use(...)` 后断言 `shot.weapon` 的箭道数）覆盖了真实接线下的
    live 装填清空与箭道快照。
- [x] **生物专用弩逐发耐久**：猪灵即时射击和掠夺者蓄力完成后的发射共用原版逐箭耐久；主副手正确扣除，多重射击中途损坏仅保留已发射射线，最后一箭保留武器快照，未命中照常付费。蓄力开始或被遮挡取消时不提前扣耐久。专用生物动作仍使用原有普通箭来源，不等同于玩家已装填特殊弹药适配。
- [ ] **原版消耗语义后续核验**：其他特殊物品和第三方事件取消边界。玩家物品入口完成不代表任意模组回调都已兼容。
- [x] **玩家斧破盾**：保留原版实际格挡与 canDisableShield 判断，原版盾的 100 tick 破盾冷却接为 500 AV；选择的快捷栏武器生效，正面格挡、背后攻击及非破盾物品分别处理；退出恢复剩余原版冷却。不改卫道士专用动作，不新增击退；模组自定义盾牌另行适配。
- [x] **物品不可用原因**：快捷栏不可用时仍可点击查看原因；未启用物品单独说明，不可用动作加 × 并在点击时展示服务端原因且不提交。显示弹药所需/现有数量、剩余冷却 AV、行动资源不足及目标原因；弹药堆叠不足说明不会跨堆叠补足。客户端点击、提示布局待实测。

验收：已有组件值修改后即时反映在战斗效果中；预览零消耗；一次使用只结算一次；客户端与服务端对选择结果一致。

### 第二组：三叉戟（P1）

玩家三叉戟已新增显式映射，开放基础近战、普通投掷、忠诚 AV 返回、引雷和自由落点激流冲刺。溺尸仍使用独立的原版生物投掷路径。

- [x] **近战**：注册玩家三叉戟，复用原版攻击属性、耐久和伤害附魔。
- [x] **基础投掷**：目标选择与远程判定，调用原版投掷命中、保存武器组件；提交时将一把武器转为目标处的可回收掉落物，扣一次投掷耐久，不生成实时伤害投射物。无忠诚的未命中/取消不退回背包，战后拾回；物品生成被取消时不扣武器和行动。具有激流强度时改用冲刺，不投出武器。
- [x] **忠诚 AV 返回**：投掷后按 `loyalty_return_av / 忠诚等级` 返回，默认 100/50/33.33 AV；命中与否均计时，离战提前回收。原槽位被占时尝试背包，满包则落在脚边；只转移存活的真实掉落物，不重建已销毁物品。保留原版组件、耐久与独立行动冷却。
- [ ] **回收后续**：两件事都**未实现**，不要混为一谈 ——
  ① **无忠诚战内回收操作**（把落地掉落物取回背包的动作）**尚未实现**，负责人 Codex（A06）；
  ② **断线/重启实际拾回验收**属验证缺口，方案见 D05。
  已实现的部分：忠诚 AV 返回（含返回动画），以及所有投掷物都用真实持久化掉落物。
  已投掷武器自然消失不成立，但会受原版环境伤害摧毁；普通战内拾取保持锁定；
  返回任务本身**不跨服务器重启保存**。
- [x] **穿刺**：近战与投掷复用原版目标标签和伤害附魔计算。专项验证无附魔及 I–V、离水守卫者、水中远古守卫者、水中溺尸/掠夺者不额外增伤、护甲韧性减伤、选择槽位恢复、投掷快照和重复提交；不另写生物名单或固定额外伤害表。
- [x] **引雷**：原版附魔回调判定雷暴、露天及成功投掷命中；雷击改为同场参与者一次结算，含友军，保留原版雷伤/事件/苦力怕充能，点燃后按 AV 推进。视觉不再产生伤害、供电、生火或铜块除锈。天气/屋顶/未命中/近战/免疫目标/事件取消、范围过滤和视觉隔离通过服务器测试；客户端闪电音效待实测。
- [x] **激流结算与入口**：用户选择自由落点冲刺，途中接触首个敌人攻击一次。水/雨条件、原版激流强度换算 6/9/12 格曼哈顿距离、主要行动 1/耐久 1/200 AV 冷却，保留普通移动；公共技能位移、预览与提交时碰撞检查、周身范围内直接发动、武器快照、出水重力与累计摔伤、退出取消通过服务器验证。数据包可覆盖距离倍数/上限、行动成本、冷却。
- [ ] **激流表现验收**：客户端落点、Q/E 深度选择、路径、朝向、联机插值及音效实测**均未做**。
  **原版旋转姿态不接入是刻意决定**，不是遗漏：原版激流旋转会追加实时伤害，在纯表现路径启用等于
  绕过战斗结算；若要做必须先屏蔽其伤害与碰撞，属独立议题（见 `ACTION_ANIMATION_PLAN.md` §14.1
  与 A12 说明）。

验收重点：同一三叉戟唯一归属，命中/未命中/中途退出均不复制；各附魔保留原版适用条件。

### 第三组：末影珍珠与紫颂果（P1）

- [x] **末影珍珠首版**：自由选点、曼哈顿 16 格、战场内可见的合法地面/水中落点，消耗主要行动 1/珍珠 1/默认 100 AV；原版 5 点摔落类型自伤和 NeoForge 珍珠传送事件。检查身体碰撞、占用、世界边界、区块加载、落点支撑及事件修改后的坐标；原版物品冷却入战继承、战中 AV 推进、离战恢复。客户端入口/联机实测待做，随机末影螨暂未生成。
- [x] **紫颂果首版**：原版 FOOD 组件进食（含满饱食度使用、转换物品与无限材料），最多 16 次随机尝试、8 格曼哈顿范围、战场内有支撑且无液体落点，可穿墙传送但不可落入方块。默认消耗 1 次主要行动/1 个食物/100 AV；无合法落点或事件取消同样消耗，取消立即停止尝试。支持 NeoForge 紫颂果传送事件并重检坐标；原版冷却入战继承、战中 AV 推进、离战恢复。骑乘/睡眠拒绝，客户端实测待做。
- [x] **通用战斗传送接口首版**：BattleAccess.previewTeleport/teleportTo 对玩家与生物开放只读预检和付费效果提交；CombatTeleport.Rules 控制范围/视线/水中落点，Result 返回规范化落点或错误。提交重检，限定同场存活实体与有效执行上下文；拒绝骑乘/载客及运动中提交，成功清除摔落并同步锚点。数据包 teleport_offset 效果与可安装示例已提供，见 TELEPORT_API.md。骑乘整体传送、飞行悬停落点及通用选点 GUI 后续扩展。
- [x] **珍珠首版传送限制**：可摆脱周身控制，不花普通移动距离；不允许传送离开战场，不通过墙体选择落点；骑乘/睡眠时拒绝。紫颂果允许跨墙寻找安全落点，与珍珠的可见落点限制分开。

验收重点：不钻墙、不悬停水面、不越界、不借原版实时冷却重复使用；退出后原版冷却恢复一致。

### 第四组：重锤（按用户决定跳过额外机制）

用户确认：通过进战的那次原版攻击打出下落爆发，进入回合制后只能普攻。取消战中蓄落差、重击窗口、致密专用加成和风爆位移等制作任务。

- [x] **普通近战**：重锤加入原版武器默认映射，复用原版攻击属性、耐久和普通附魔路径；战斗执行器在伤害/命中附魔结算前清除下落距离，避免触发重击和风爆。
- [x] **入战首击边界**：不改场外原版攻击流程，首击沿用原版下落爆发与附魔；战中不保存下落爆发资格。没有新增跳跃/重击行动。

### 第五组：被动装备与副手操作（P2，战斗换装已取消）

预先穿戴的装备可能已经通过原版伤害/属性流程生效；本组先验证缺口，不重复制作已经正常工作的被动效果。

- [x] **不死图腾**：复用原版主副手致死保护、消耗、解除状态与复活效果，验证救活后仍留在战斗中；再生/伤害吸收/抗火按 AV 推进、现实等待冻结、离战恢复读秒。背包图腾不自动救命，NeoForge 图腾取消事件保持有效；没有新增主动行动。客户端复活动画待实测。
- [x] **护甲/海龟壳/皮革装备首轮**：下界合金全套原版护甲/韧性/耐久、保护附魔与摔落保护通过专项验证；皮革装备保留原版防冻判定。海龟壳改为每个 AV 状态 tick 调用原版刷新方法，现实等待不刷新；水下消耗剩余水下呼吸，露出水面按 AV 刷新至 200 tick，离战恢复实时刷新。客户端显示待测。

## 4. 暂缓或不开放的物品

以下分类也属于原版覆盖结论，不要求给每种物品强行增加战斗技能。

| 物品 | 当前范围决定 |
| --- | --- |
| 普通方块、TNT、床、重生锚、末地水晶 | 不开放战斗中放置或交互爆炸；若以后制作独立技能，必须另行定义 |
| 水桶、岩浆桶、粉雪桶、装生物的桶 | 暂不开放倾倒、收取或释放；牛奶桶按已实现饮用处理 |
| 打火石、火焰弹 | 不开放点火；不因火焰弹是物品就赋予玩家恶魂火球能力 |
| 钓鱼竿 | 暂缓；钩住/拉拽需要独立目标、控制及位移方案 |
| 经验瓶 | 暂缓；经验实体、拾取与经验修补联动需先明确战斗规则 |
| 鞘翅及推进烟花 | 暂缓主动飞行，依赖玩家飞行移动方案；弩用烟花已有支持 |
| 鞍、马铠、胡萝卜钓竿、诡异菌钓竿 | 既有预先骑乘能力保留；战斗内装配、上马和加速属于骑乘后续组 |
| 动物食物用于驯服/繁殖、命名牌、拴绳、刷子、剪刀、骨粉 | 资源与非战斗交互，当前不开放；可食用物品仍能按食物规则自用 |
| 地图、指南针、时钟、望远镜、书、乐器、材料及其余资源物品 | 不增加战斗行动；铁锭和犰狳鳞甲等已有明确修复用途的例外保留 |
| 刷怪蛋、命令/管理物品 | 不作为生存战斗行动开放 |

## 6. 每组完成标准

1. 物品映射、行动定义、效果执行与 GUI 入口完整；数据包可覆盖必要参数。
2. 原版组件、附魔、耐久、容器和创造模式语义有明确对应关系。
3. 目标死亡/离场、物品变化、行动不足、冷却中、断线和战斗结束不会复制物品或重复扣费。
4. 范围效果和延迟效果受同场参与者规则约束；合法敌我伤害不会误扩散到场外实体。
5. 对新增高风险结算与回归缺口做服务器验证；目标选择、动画、提示和联机同步进行客户端实测。
6. 更新本文件与任务表。功能完成、服务器验证、客户端待测分别说明。

推荐顺序：**第一组一致性与选择体验 → 第二组三叉戟 → 第三组传送物品 → 第四组重锤 → 第五组装备 → 第六组低优先级投掷物/表现**。扩展文档和接口随对应组补齐。
