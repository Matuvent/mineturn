# 回合次数、计时与技能位移

每回合默认 1 次主要行动、1 次次要行动。GUI 显示当前行动者的剩余次数、剩余移动距离和玩家操作倒计时。已有物品、疾跑、撤退、逃跑默认消耗一次主要行动；玩家默认物品尚未分配次要行动。动作现在可通过 parameters.action_cost 配置主要/次要次数，物品、条件动作和 AI 共用，见 [ACTION_COSTS.md](ACTION_COSTS.md)。

两个原版属性接口支持装备属性修饰器、附属模组及 `/attribute` 命令：

```mcfunction
attribute @s mineturn:main_actions base set 2
attribute @s mineturn:bonus_actions base set 1
```

范围 0–100，开始新回合时读取，向下取整；修改属性不会追溯增加当前回合次数。已提交技能的 `CombatEffects.Context.battle()` 可调用 `changeActions(mainDelta, bonusDelta)` 增减当前行动者的剩余次数，或 `spendBonusAction()` 消耗一次次要行动。越界、非当前行动者、预检与失效上下文调用会拒绝。额外主要行动不会绕过物品冷却或资源消耗。

mcfunction AI 可查询 `mineturn ai query main_actions` 与 `mineturn ai query bonus_actions`，返回原始整数。旧的 `can_act` 查询继续表示是否还有主要行动。现有内置模板自行结束移动回合的规则不变。

## 30 秒操作期限

玩家每回合有 600 个服务器 tick（正常运行约 30 秒）操作时间，服务器每秒同步显示。成功消耗主要行动、次要行动或移动距离后重置为 30 秒；无效请求、预览、转镜头、仅修改次数不重置。移动动画和远程判定期间暂停计时，超时自动结束回合。服务器卡顿会延长现实时间，AV 不随倒计时流逝。

**期限是"上次有效操作后的宽限"，不是回合总时长上限。** 因此只要玩家持续做出有效操作（含每次移动），期限会不断刷新，回合不会因累计时间过长而被强制结束；只有**连续 30 秒没有任何有效操作**才会超时。界面上的倒计时在每次有效操作后回到 30 秒是预期表现，不是显示错误。这是刻意设计：玩家需要时间观察战场与选择目标，但不应借此无限拖延。

## 技能专用强制位移

普通攻击继续无击退。技能执行或托管延迟回调中可以调用：

```java
boolean moved = context.battle().displace(context.target(), new Vec3(2, 4, 0));
// 自身位移可将 context.source() 作为目标。
```

位移参数是世界坐标偏移，曼哈顿长度上限 40。接口只接受本场活着的参与者，拒绝运动正在执行时叠加位移；逐段检查实体体积碰撞、世界边界和已加载区块，遇障碍停在可达前段。它不消耗移动距离，不受周身范围限制，不授予额外行动。

地面目标抵达后立即结算落下及原版摔伤，飞行目标保留高度。当前为服务端即时位置结算，没有抛物线播放或持续空中受控状态；也不跨越液体边界。接口返回是否产生位移。预检或已过期的技能上下文不能调用。新的技能尚需自行注册效果并编写动作 JSON。
