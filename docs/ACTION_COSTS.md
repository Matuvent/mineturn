# 数据包行动成本

物品动作、右侧条件行动、mcfunction AI 和状态机 AI 共用动作定义中的 `parameters.action_cost`。

```json
{
  "name": "快速治疗",
  "effect": "mineturn:heal",
  "amount": 4,
  "range": 1,
  "self": true,
  "cooldown_av": 100,
  "parameters": {
    "action_cost": {"main": 0, "bonus": 1}
  }
}
```

此示例是动作定义；还需通过物品映射或 grants 将它提供给玩家。外部数据包/附属模组可以新增动作，或同路径覆盖已有动作。没有默认把进食或其他原版动作改成次要行动。

## 格式与兼容

- 不写 `action_cost`：一次主要行动，保留旧数据包默认行为。
- `"main"`：一次主要行动；`"bonus"`：一次次要行动，兼容此前函数 AI 写法，现在也适用于玩家和状态机。
- `{"main":2,"bonus":1}`：同时消耗两次主要行动和一次次要行动。对象中省略的字段按 0 处理。
- 两项必须为 0–100 的整数且不能同时为 0；拒绝空对象、负数、小数、数字字符串、未知字段和 null。与现有每类最多 100 次行动的上限一致。
- 成本属于动作本身，同一动作从物品、grants 或 AI 发起时使用相同规则。grants.cost 仍是经验/魔力等独立资源成本，不是行动次数。

## 执行规则

先检查回合、目标、行动次数、材料、冷却及效果限制，再支付。两类行动次数一起检查、一起扣除；其中一种不足时不会先扣另一种，不会消耗物品、弹药或 grants 资源，也不会重置操作倒计时。

成功支付会记录一次操作活动，按既有规则重置玩家 30 秒操作倒计时。消耗次要行动不会隐式扣掉主要行动，反之亦然；不会修改剩余移动距离。

远程动作在发起判定时预付完整行动成本、资源/弹药和冷却。未命中、判定超时或结算时条件失效不退款；重复提交不会再次结算。预览、悬停和可用性检查不扣费。

快捷栏和右侧条件行动的悬停提示显示主要/次要行动成本；按钮使用服务端逐动作检查结果，因此主要行动用完不会错误禁用仍能支付的次要动作。数量不足时说明所需次数和当前剩余次数。

函数 AI 的 `query can_act` 继续表示主要行动是否可用，`query main_actions`、`query bonus_actions` 保持现有语义。脚本可使用 `mineturn ai query ready <动作>` 检查具体动作；行动执行本身始终再次校验。函数脚本应在同一次 on_turn/on_move_finished 回调内完成需要的主要/次要动作；主要行动耗尽后的回调收尾沿用旧行为。状态机选择动作时过滤无法支付的候选；主要行动归零后，仅当前状态仍有成本可支付且冷却就绪的候选才继续检查，无可执行进展时结束回合。

## 网络与验证

网络协议升级为 13，客户端和服务器必须一起更新。完整构建成功，175 项服务器 GameTest 全部通过。服务器回归覆盖严格格式检查、混合成本原子支付、次要进食、条件技能资源/远程预付、重复提交、两种 AI 入口及成本网络编解码；客户端悬停布局需游戏内实测。
